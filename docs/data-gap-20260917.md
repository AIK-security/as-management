## 10. ✅ 現場マスタの起こし方 ─ 論点5 の答え（2026-09-17）

> 🔴 **方針の確認（2026-09-17 柴山）**
> 本件は「**今あるものを置き換える**」より、「**いまやっている仕事を整理して楽にし、無駄を省く**」ことが目的。
> この観点で §2 を読み直すと、**現場名がマスタに無いことは「移行できない困りごと」ではなく、
> 「毎日打っているものを消せる余地」**になる。

### 10-1. 何が起きているか

| | |
|---|---|
| 現状 | 管制は毎日、現場名・区分・時刻・人数を手で打っている。**7月は延べ 1,899回**（1日61行） |
| 原因 | ShiftMax 側に**現場が存在しない**（§2）。打つ以外に方法が無い |
| ✅ | **現場名が残っているのは、その手入力テキストだけ。** そこから起こせば二度と打たなくてよい |

### 10-2. 実測（`scripts/extract-sites.py`）

| | 件数 |
|---|---|
| **現場として起こせた** | **154 件** |
| 現場ではないため除外（休み・内勤・教育・現中） | 16 件 |
| 勤務マスタと警備先番号が照合できなかった | **0 件** ✅ |

| 起こせた属性 | 一定に定まる件数 |
|---|---|
| **区分**（日勤85／夜B41／夜A27／夜勤1） | **154件すべて** ✅ |
| **開始・終了時刻** | **115件（75%）** |
| **必要人数** | **114件（74%）** |
| 顧客名・管轄・現場コード | **154件すべて**（勤務マスタから照合） |

→ **現場を選べば、警備先番号・区分・時刻・人数が7割の現場で自動的に埋まる。**
　 いま毎日61行ぶん打っているものが「選ぶ」に変わる。

### 10-3. 使い方と置き場所

| | |
|---|---|
| スクリプト | `scripts/extract-sites.py`（**開発ツール。`src/` の外**・`dummy-data.mts` と同じ扱い） |
| 実行 | `python scripts/extract-sites.py` |
| 出力 | `local/sites-extracted.csv`（Excel でそのまま開ける） |
| 🔴 | **出力は Git に入れない**（`local/` を `.gitignore` 済み）。取引先実名・現場名が入るため |
| 用途 | **一度きりの初期データ作成**。第1弾の稼働後は使わない |

### 10-4. 🟠 残る確認（管制へ・10/1）

### 10-5. ついでに解けたこと

🔴 **§2-2 の「段3 は N:1 の写像になる」は解消する。**
起こした154件は**警備先番号を属性として持っている**ため、ShiftMax へ渡すときは 1:1 で写せる。
（段3 の要否そのものは事務側ヒアリング待ちで変わらない）
