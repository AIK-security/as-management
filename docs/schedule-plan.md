## 5. 定着施策

> **AS が過去に離脱した主因は「業務との構造的不一致」と推定されている。**
> 作って渡すだけでは同じことが起きる。以下を工程に組み込む。

| # | 施策 | 期間 | ねらい |
|---|---|---|---|
| 🔴 **0** | **段1 の時点で画面を見せる**（9/11） | 9月上旬 | **最重要。** 作り切る前に不一致を発見する。<br>AIK assign は**完成させてから気づいた** |
| 1 | **現場パイロット**（紙と並行） | 11/2-11/13 | **業務を止めずに**不一致を洗い出す |
| 2 | **並行稼働**（A表とシステム両方） | 11/30-1/8 | 出力が Excel と一致するか検証。請求・労務側の安心を作る |
| 3 | 操作マニュアル（画面キャプチャ付き） | 11月 | 管制3名（菊池・赤尾・安藤）が同じ手順で使える |
| 4 | **1日の流れに合わせた導線** | 設計済 | 9:00 仮組み → 10:00 清書 という**既存の順序を変えない** |
| 5 | **慣れた操作体系を変えない** | 設計済 | 現行もプレートの D&D。**ホワイトボードのメタファーを維持** |

### 最初に届ける実感

> **「べんり君への入力 1.5時間/日 がゼロになる」**

パイロットの初日にこれを体験してもらう。
**「システムが増えた」ではなく「作業が減った」**という最初の印象を作れるかが定着を分ける。

> 🔴 **だからこそ「新システムとべんり君の二重運用」だけは避ける**（8/31 決定）。
> 貼り付け方式を不採用にしたのはこのため。詳細は `screen-design.md` §3-2。

## 7. 🔴 このスケジュールを変える唯一の要因（外部要因は消滅した）

**残る変数は1つだけ：事務側が ShiftMax で何をしているか。**

```
経路①（現設計）  新システム → ShiftMax → 事務 → 請求書・給与
経路②（未検証）  新システム ────────────→ 事務 → 請求書・給与
```

| 判定結果 | 段3（9/28-10/9）がどうなるか | 期間への影響 |
|---|---|---|
| **ShiftMax の画面を見て Excel に転記している** | 🟢 **投入工程が丸ごと不要。** `S-20` 出力だけでよい | 🟢 **短縮**（べんり君の改造も不要） |
| **ShiftMax から出力して使っている** | 🟠 同じものを新システムが出す | 🟢 やや短縮 |
| **ShiftMax が勤怠・給与を計算している** | 🔴 投入が必要。べんり君のコピーに送信機能を追加 | 変わらず（本案どおり） |

> 🔴 **判定は 9月上旬の事務側ヒアリング**（`hearing-jimu.md` ★A-3 / ★B-1）。
> 🟢 **段1・段2（9/1-9/25）はどの結果でも変わらないため、判定を待たずに着手する。**

> 📌 **旧 v1.0 §7「ShiftMax の契約更新時期」は削除した。**
> 月額・月払い・違約金なし・期間拘束なしのため、**「更新月を跨ぐと1年分が無駄になる」という
> シナリオ自体が存在しない**。急ぐ理由は契約側には無い。

## 8. 社長への説明の骨子

> ⚠️ 現場向けの説明は「負荷軽減・工数削減・アナログ作業の撲滅」で一貫させる（CLAUDE.md）。
> 以下は**経営層向け**。

### 言うこと

1. 🟢 **「11/2 に現場が触り始める」という当初の約束は守れます。**
   変えるのは**その日に一発で切り替えない**ことだけ。11/2 は**紙と並行のパイロット開始**です。
2. **一発切り替えは業務停止のリスクを取ることと同義。**
   A表は請求・労務すべての情報源で、**止まると給与と請求が止まります**。
3. **暫定案には「現場が使い始めてから定着するまで」の期間が1日も入っていませんでした。**
   AS は一度、システムが定着せず離脱しています。
4. 🟢 **要件定義と設計は前倒しで完了しました**（8/28-8/31）。
   構築方式・技術スタック・データモデル・画面設計が確定済みで、**9/1 から開発に入れます**。
5. **浮いた3週間は開発期間に回しました**（5週 → 8週）。
   8月のヒアリングで**要件が増えた**ため（協力会社の個人管理／応援の双方向／NGリスト）、
   期間を削らずに吸収するための措置です。

### 同時に出すこと（隠さない）

| | 内容 |
|---|---|
| ✅ | **ShiftMax の契約条件が判明しました**：99,000円/月・月払い・2ヶ月前申請・**違約金なし**<br>→ 🟢 **契約側に急ぐ理由はありません。** いつでも降りられます |
| 🔴 | ただし **ShiftMax は第1弾では解約できません。** 事務側が使っているためです<br>→ **年118.8万円は第2弾まで持ち越し** |
| 🔴 | **バックアップ要員は確保しない前提に変更しました。**<br>代わりに「保守しやすさ」を設計要件に格上げしています |
| 🟠 | **登録枠が残46人**しかないことが判明（上限300人／現在254人） |

### 言わないこと

- 🔴 **「ShiftMax の年118.8万円が削減できます」とは言わない**（8/27 決定・継続）。
  第2弾で確定してから**一度だけ**出す。
  → 一度出してから「第2弾まで出ません」と訂正すると、試算全体の信頼性が落ちる
- **人員最適化の話**（現場に伝わるルートを作らない）
