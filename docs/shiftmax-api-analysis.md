## 0. 結論

**方式 A（API）で確定。** 画面自動操作（C）でもファイル取込（B）でもない。

べんり君は、ShiftMax 側に用意された**管制専用の HTTP エンドポイント**に対して
`MSXML2.ServerXMLHTTP` で同期 POST しているだけであり、ブラウザは一切介在しない。

| 8/27 時点の想定 | 8/28 の判明結果 |
|---|---|
| A:API / B:CSV取込 / C:画面自動入力 のいずれか不明<br>🔴 **工数が桁で変わる** | ✅ **A（API）**。<br>新システムからは「フォームエンコードで POST する」だけで足りる |

## 1. 通信仕様

```
POST https://kn005.shiftmax.jp/ExcelConnectionKansei.ashx
Content-Type: application/x-www-form-urlencoded;charset=UTF-8
```

- 実装：`modWeb.bas` / `Public Function fncSend2`
- HTTP クライアント：`MSXML2.ServerXMLHTTP`（`fncCreateXmlHttp`）。**同期実行**
- エンドポイント名は定数 `C_ASHX = "ExcelConnectionKansei.ashx"`（`modWeb.bas:4`）
  - `.ashx` ＝ ASP.NET の汎用ハンドラ
  - 名称に `Kansei` が入っている＝**管制向けにベンダが用意した接続口**であり、
    ShiftMax の汎用 API ではない可能性が高い（→ §5 の確認事項）
- ホスト（URL）は「設定」シートの `URL` 項目から読む。ハードコードではない

### 1-1. 共通リクエストパラメータ

| キー | 内容 |
|---|---|
| `LoginID` | ログインID |
| `LoginPWD` | パスワード |
| `SrcVersion` | べんり君のバージョン（設定シート。現在 `1.0.007`） |
| `XlsVersion` | `Application.Version`（Excel のバージョン） |
| `Arg***` | リクエスト種別ごとの引数（下記） |

🔴 **認証情報は毎リクエストのボディに平文で乗る**（通信自体は HTTPS で保護される）。

### 1-2. レスポンス仕様

**CSV**（`fncSplitCsv` でパース）。

| 行 | 内容 |
|---|---|
| 1行目 | `結果コード, 表示用メッセージ, 例外メッセージ` — 結果コード `0` が正常 |
| 2行目 | CSV 項目名（ヘッダ） |
| 3行目以降 | データ |

- `Content-Disposition` に `attachment` が含まれる場合はダウンロード扱い（`responseBody` をそのまま受ける）
- 前処理として、パラメータ無しの `GET` を1回投げている（`ObjXmlHttp.Open "GET"` → `send("")`）。
  コード中のコメントによれば **ServerXMLHTTP のエラー回避のためのワークアラウンド**

## 2. API の全体像（リクエスト種別は 2 つだけ）

`ArgReqType` の値は全モジュールを通じて **`マスター` と `管制更新` の 2 種類のみ**。

### 2-1. マスタ取得（読み） `ArgReqType=マスター`

`ArgTable` で対象を指定する。実装：`modMaster.bas`

| `ArgTable` | べんり君側の格納先シート |
|---|---|
| `隊員` | 社員マスター |
| `現場` | 勤務マスター |
| `顧客担当` | 得意先マスター |
| `管轄` | 管轄マスター |
| `部署` | 部署マスター（＋部署コンボボックス用リストを生成） |
| `年月コード` | 年月マスター |
| `日コード` | 日マスター |
| `体験版日付` | （体験版判定用。実運用では不使用） |

> **ShiftMax がマスタの本体**であることがコード上でも裏付けられた。
> べんり君は起動時にこれらを取得してシートへ展開しているだけで、マスタを保持していない。

### 2-2. 管制更新（書き） `ArgReqType=管制更新`

実装：`modKansei.bas` / `Sub fncUpdate_Kansei`（「更新ボタン」から呼ばれる）

| キー | 内容 |
|---|---|
| `ArgReqType` | `管制更新` |
| `ArgNenTukiHi` | 年月日 |
| `ArgKankatu` | 管轄 |
| `ArgCsv` | 配置データ（CSV 文字列・全件） |

- **「日付 × 管轄」を単位として、その範囲の配置データをまとめて送る**
- サーバ側はエラー時に「行・区分・項目・メッセージ」を返す。
  区分の値は `0:未更新 / 1:追加完了 / 2:更新完了`
  → **行単位の upsert（追加 or 更新）**とみられる
- 🟠 **削除の扱いは不明。** 警備先番号が空の行は CSV に含めずスキップしている

## 3. 🔴 投入 CSV の項目定義（第1弾の出力仕様そのもの）

`modKansei.bas:74`（`fncCreateCsv_Kansei`）で定義。**18列・固定順**。

| # | 項目名 | 備考 |
|---|---|---|
| 1 | 日付 | |
| 2 | 現場コード | 勤務マスターから警備先番号で引く。**未登録ならエラーで送信中止** |
| 3 | 警備先番号 | 管制シートの入力キー |
| 4 | 現場名 | |
| 5 | 班名 | |
| 6 | 開始時間 | 時・分が別項目 |
| 7 | 開始分 | |
| 8 | 終了時間 | |
| 9 | 終了分 | |
| 10 | 昼休憩 | |
| 11 | 個人コード | 未割当は `0` |
| 12 | 隊員ナンバー | 未割当は `0` |
| 13 | 社員名 | 未割当は空 |
| 14 | 予定コメント | |
| 15 | リーダー | `0/1`。ヘッダ名は設定シートで差し替え可 |
| 16 | サブ | 同上 |
| 17 | 遠距離 | 同上 |
| 18 | 請求備考 | |

- 全項目が `"` で囲まれる。値中の `"` は `""` にエスケープ
- 行区切りは `CRLF`、末尾にも `CRLF`
- ヘッダ行あり（1行目が項目名）
- **リーダー／サブ／遠距離のヘッダ名は「設定」シートの値で置換される**
  （`チェック項目*` にマッチする場合は `計算用チェック*` に読み替え）
  → 新システムでも**ヘッダ名を設定可能にしておく**必要がある
- 🔴 **2026-10-07 確認：設定シート（9月のべんり君と思われる）の「リーダー」「サブ」「遠距離」は3つとも空。**
  値が空だと見出しも空文字で送られる（中身の `0/1` は各行に入る）。
  → **今の運用では ShiftMax にリーダー・サブ・遠距離は入っていない可能性が高い**（サーバ側の扱いは未確認）
  → 18列CSV（`/handoff`）は見出しを「リーダー／サブ／遠距離」のまま出し、
  　**べんり君側の読み込みマクロで設定シートの値に書き換える**（今の送信と同じ処理）。設定が変わっても送る中身は揃う

> 🔴 **この18項目が、第1弾（管制）が最低限保持しなければならないデータ項目。**
> 逆に言えば、**ShiftMax へ渡すという目的だけならこれ以上は要らない**。

### ✅ 7-6-2. `ArgNenTukiHi` の書式 ─ **確定（2026-08-31）**

VBA の該当箇所（更新ボタンの Click ハンドラ・全32フォームに同一コードが複製されている）：

```vb
strNenTukiHi = "" & cmbNenTuki.Value                     ' 例: "202607"
strNenTukiHi = Left(strNenTukiHi, 4) & "/" _             ' "2026"
             & Right(strNenTukiHi, 2) & "/" _            ' "07"
             & cmbHi.Value                               ' "1"
If Not IsDate(strNenTukiHi) Then                         ' 妥当性チェック
```

| | 結論 |
|---|---|
| ✅ **書式** | **`YYYY/MM/D`** ─ **年月コード体系ではなく、ただの日付文字列**<br>例：`2026/07/1` `2026/07/15` `2026/12/31` |
| ✅ **月** | **2桁ゼロ埋め**（年月コードが `YYYYMM` のため必然的にそうなる） |
| 🔴 **日** | **ゼロ埋めしない**（日コードが `"1"`〜`"31"` のため）。**`2026/07/01` ではない** |
| ✅ **区切り** | スラッシュ `/` |
| ✅ **検証** | 送信前に VBA 側で `IsDate()` チェックが入る |

> 🟠 **サーバ側がゼロ埋めを許容するかは未検証。**
> 現行が `D`（ゼロ埋めなし）で通っている以上、**新システムも `D` に合わせるのが安全**。
> `MM` に合わせて `DD` にしたくなるが、**揃えない**。

#### 🔴 実装時の注意（1名体制ゆえの落とし穴）

JavaScript / TypeScript で素直に書くと **`padStart(2,'0')` を日にも掛けてしまいがち**。
アダプタでは以下を固定する：

```ts
// ShiftMax の ArgNenTukiHi 書式：YYYY/MM/D（日はゼロ埋めしない）
const toShiftMaxDate = (d: Date) =>
  `${d.getFullYear()}/${String(d.getMonth() + 1).padStart(2, '0')}/${d.getDate()}`;
```

#### ✅ 同じ値が CSV の第1列にも入る

`fncCreateCsv_Kansei` 内で `Case "日付": arrVal(lngClm) = strNenTukiHi`。
**`ArgNenTukiHi` と CSV 1列目の「日付」は完全に同一の文字列**。片方だけ書式を変えてはいけない。

### 8-3. 🔴 隊員の割当は「プレートのドラッグ＆ドロップ」

**セルへの入力ではない。** 隊員は Excel の**テキストボックス図形（社員プレート）**として
画面右（X〜AL列）に並んでおり、それを S/T/U 列へドラッグして配置する。

- 判定ロジック：`fncGetMemberPlate`（`modKansei.bas:379`）が**図形の座標**を読み、
  どの行のどの列に置かれたかで所属を決める
- 設定シートに `社員プレート幅=55` `高さ=16` `最終行=30` `他管轄列数=5`
  `幅はみ出し許容比率=0.4` `高さはみ出し許容比率=0.3` があり、
  **プレートがセル境界からずれても所属行を判定する**ための閾値になっている
- **リーダー / サブ**：プレートが S列 / T列 のどちらに置かれたかで決まる
- 🔴 **遠距離**：**プレートの文字色**が設定シートの「遠距離対象者プレート文字色」と
  一致するかで判定（`modKansei.bas:474`）
- 個人コードの特定は**プレートに書かれた氏名（または略称）で社員マスターを文字列検索**
  （`fncMatchStr`）。コードでは突合していない

> **これはホワイトボードのメタファーをそのまま Excel に持ち込んだもの。**
> 8/27 の「A表で仮組み → WB で決定 → A表に上書き」という運用と完全に整合する。
