| 問題 | 内容 |

### 2-3. 🔴 10 が消えた理由（最重要）

7月31日分・4,281行・プレート3,803枚を集計した結果：

| | |
|---|---|
| プレート上の協力会社名（東京世紀 / フェニックス 等） | **0件** |
| プレート上の「応援」 | **65枚**（全日2枚）。表記は `応援` の1種類のみ |
| 社員マスター（250行）中の該当 | **「応援　東京」1件のみ**（`個人コード=524` / `隊員ナンバー=10`） |

> **事務側は協力会社の個人名を受け取っていない。その状態で給与・請求が回っている。**
> 個人名が必要なのは**管制だけ**（連絡先・現場経験・NG の判断）。
>
> → ✅ **新システムは協力会社の隊員を個人単位で持つが、ShiftMax へは「応援」枠として送る。**
> 　 **300人枠を消費せず、事務側の受け取るデータも変わらない。**

## 3. ✅ 採用する方式：べんり君経由（貼り付け）

```
新システムで配置を組む
   ↓ 「べんり君貼付用」データを出力
べんり君の管制シートへ貼る → 管轄・日付を選んで「更新」
   ↓ （マクロが従来どおり POST）
ShiftMax
```

| | 直接POST（8/28 の決定） | **べんり君経由（8/31 変更後）** |
|---|---|---|
| ベンダ照会 | 🔴 必須 | ✅ **不要** |
| 認証情報 | 🔴 専用アカウントが要る | ✅ **新システムが持たない** |
| 費用削減 | **0円**（月額は変わらない） | **0円**（同じ） |
| 管制の作業 | 0分 | 数分/日（**年20時間**） |
| 実装 | HTTP・認証・エラー処理 | ✅ **出力フォーマット1つ** |
| 第2弾での破棄 | アダプタ1本 | ✅ **出力1つ。より捨てやすい** |
| サーバから見た挙動 | 🟠 新しいクライアントからの書き込み | ✅ **現行と完全に同一** |

> 🔴 **直接POST で買えるのは年20時間だけ。** ShiftMax を使い続ける限り**費用は1円も動かない**。
> 費用（99,000円/月）が消えるのは**第2弾だけ**。
> **年20時間のためにベンダ関係・規約・鍵の複製リスクを取るのは釣り合わない。**

### 🔴 なぜ「共有アカウントを流用して直接POST」も採らないか

「べんり君の平文共有アカウントを使えば専用アカウントは要らないのでは」に対して：

| | 技術的には | しかし |
|---|---|---|
| 動作 | ✅ **完全に動く**。サーバから区別できない | ─ |
| 規約 | ─ | 🔴 アカウントの有無と**無関係**に残る |
| 監査 | ─ | 🔴 全員が同じID。**ShiftMax 側の記録は全部同じ人**になる |
| 鍵の管理 | ─ | 🔴 **共有のためパスワードを変更できない**（変えるとべんり君が止まる）。<br>**回せない鍵の複製を新システムにも置く**ことになる |

→ 8/27 決定「べんり君の平文共有アカウントを新システムに持ち込まない」を維持する。
