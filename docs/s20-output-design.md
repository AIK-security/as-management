## 3. 決定事項（2026-09-24・柴山）

### 3-1. 計算方法・請求単位は変えない

新システムは**集計表の計算そのもの**には手を出さない。**日報チェック表に入る数字を、正しく・漏れなく出す**ところまで。
計算方法は第2弾でも**今の形を正**として移植する。

### 3-2. 残業・諸経費の入力者は「事務が主、管制も入れられる」

| 案 | 判定 | 理由 |
|---|---|---|
| **A. 事務が入れる** | ✅ **採用** | いま**日報チェック表に手入力している人がそのまま**入れる。<br>**入れる人は変えず、入れる場所だけ変える**＝手数が増えない唯一の形 |
| B. 管制だけが入れる | ❌ | 管制の手数が**増える**（「手数が減る順」の原則に反する）。警備報告書は管制の手元に無い |
| C. 器と列だけ作る | ❌ | 「本当なら出せたほうが絶対に良い」に届かない |

> 🔴 **管制も入れられるようにする。** 当日変更の電話で残業が分かるのは管制であることが多いため。
>
> ⚠️ **代償：事務が第1弾から新システムを使うことになる。**
> 8/26 の段階リリースの理由（「請求・労務は当面 Excel を継続でき、**並行稼働のリスクを負わない**」）を**一部崩す**。
> 🔴 **スケジュールへの影響は未評価**（`schedule-plan.md` への反映は別途）。

### 3-3. 実績は配置と別テーブルに分ける

いまの残業の器（`actual_*`・`overtime_min`）は**配置と同じ `assignments`** にある。
**RLS は行単位で、列単位にはかけられない**。事務に残業を書かせるために `assignments` の更新を許すと、
**事務が配置そのもの（誰をどこに置くか）を書き換えられる**ようになる。

| テーブル | 中身 | 書ける人 |
|---|---|---|
| `assignments`（既存） | 配置＝**予定**。管制のもの | `control` / `admin`（**変えない**） |
| **`assignment_actuals`（新）** | 1配置に1行。**予定と違ったときだけ**値を入れる（職種・時刻・残業） | **`control` / `office` / `admin`** |
| **`shift_charges`（新）** | 枠（作業所 × 日 × 日夜）ごとの諸経費。品目・数量 | 同上 |

- RLS ヘルパーを1本足す（例：`can_enter_actuals()` ＝ control / office / admin）
- 各行に**誰が・いつ**を残す
- `assignments` の実績の器は**まだ1件も埋まっていない**。**いま移せば手戻りは無い**
- 業務棚卸の「**最終確認は警備報告書で行う**」＝〈予定は A表、確定は報告書〉の線引きとも一致する

### 3-4. 中止・キャンセルは「中止区分マスタ」で持つ（2026-09-24 改訂）

> 🔴 **当初案（`before`/`on_site` の2値を決め打ち）を改めた。**
> 柴山「中止やキャンセルについて、いくつか区分を持って設定できると便利。現着中止でもキャンセル料が発生するかしないか、とか」。
> 同じ現着中止でも請求の有無は変わる。2値では**「いつ中止したか」しか表せず、扱いの違いを持てない**。

| | |
|---|---|
| 持ち方 | **`cancel_reasons`（中止区分マスタ）** を新設し、`shifts` に `cancel_reason_id` を1列足す。<br>既存の `cancelled_at`（中止した時刻）の隣に置き、**「区分があるのに中止時刻が無い」を制約で拒否**する |
| 区分が持つもの | **いつ**（行く前／現着後）・**得意先への請求**（キャンセル料あり／なし）・**隊員への支払い**（あり／なし） |
| 🔴 請求と支払いを分ける | 得意先にキャンセル料を請求するかと、隊員に手当を払うかは**別の判断**。<br>前者は請求（第2弾）、後者は給与（第3弾）で効く。**1つのフラグにまとめると後で分けられない** |
| 🔴 マスタの値は初期値 | 区分を選べば初期値が入り、**例外だけ実績側（`assignment_actuals`）で上書き**する。<br>得意先との約束で、同じ区分でも請求の有無が変わるため |
| 行く前の中止も同じマスタ | 前日キャンセル・当日キャンセル・当社都合なども区分として持つ。**「中止の種類」の列を別に作らない** |
| 区分は書き換えない | `work_kind` を `dayCancel` に変えると**別の区分**になり、日勤の集計から落ちる |
| 誰が現地にいたか | 中止しても**配置は消さない**（9/07 の決定）ので、そのまま分かる |

**区分の例**（🟠 **すべて仮**。実際の区分は管制、請求・支払いの扱いは事務に聞く）

| 区分 | いつ | 得意先への請求 | 隊員への支払い |
|---|---|---|---|
| 前日キャンセル（得意先都合） | 行く前 | なし | なし |
| 当日キャンセル（得意先都合） | 行く前 | あり | なし |
| 現着中止（得意先都合） | 現着後 | あり | あり |
| 現着中止（雨天） | 現着後 | 要確認 | 要確認 |
| 当社都合の中止 | 行く前 | なし | なし |

- 代償：テーブル1本＋マスタ画面1つ。区分は少数のはずなので、既存のマスタ画面の形を流用する

## 5. 出力の形

**正本は明細 CSV 1本。事務が慣れた形は、それを集計して出す。**

| 出力 | 1行の単位 | 主な列 | 使い先 |
|---|---|---|---|
| **① 配置明細**（正本） | 1配置（隊員 × 枠） | 勤務日・D/N・区分・得意先・請求番号・作業所・**職種**・隊員コード・氏名・所属（自社／協力会社名）・隊長・時刻・**残業**・状態（確定／中止）・**中止区分**・請求する/しない・支払う/支払わない・備考 | ②⑦⑧ すべての元 |
| **② 日報チェック表形** | 作業所 × 日付 | ① を集計：`Ｄ誘` `誘残` `Ｄ列` `列残` `Ｎ誘` … ＋ 諸経費 ＋ **隊長名** ＋ 合計／平日／土曜／休日 | 事務が今の Excel に貼る |
| **③ 隊員別**（⑦⑧ の形） | 隊員 × 日付 × D/N | 残業時間／列車見張の有無 | 給与締め（20日） |

- **期間は開始日〜終了日の任意指定**（締め日が得意先ごと・給与は20日締め）
- **CSV のみ**。依存パッケージは増やさない（N-1）
- 🔴 **②③ は保存しない。毎回 ① から計算する**（§6-1 原則4）
- 金額は出さない（§3-1）

### 5-1. 注記：§8-2「単価は持たない」の射程

`requirements.md` §8-2 で持たないと決めたのは**隊員単価＝給与情報**（個人情報の線引きが変わるため）。
**集計表の単価は得意先への請求単価**で、個人情報ではない。**別物なのに同じ決定に巻き込まれている。**
第1弾で要らない結論は変わらない（計算は Excel に残す）が、**第2弾でこの決定を「請求単価も持たない」と読み違えないこと。**

## 6. 🔴 データの整合性 ─ AIK assign の轍を踏まない

> **AIK assign が複雑になった原因の1つ**（柴山・2026-09-24）：
> テーブルが多く、**テーブル1で加えた変更が、同じ案件のテーブル2に反映されていなかった**。

### 6-1. 原則

| # | 原則 |
|---|---|
| 1 | **1つの事実は1か所にだけ書く** |
| 2 | やむを得ず写しを持つなら、**同期は DB（トリガー・制約）にやらせる**。人やアプリに合わせさせない<br>（アプリで同期すると、別の経路から書いた瞬間に黙ってずれる） |
| 3 | **「その時点の値」を残す写し（スナップショット）は、同期しないことをコメントに明記する** |
| 4 | 🔴 **集計結果をテーブルに保存しない。** 集計は毎回明細から計算する |
| 5 | **検査 SQL で確かめる。** 写しと元が食い違う行を返し、0行なら正常（§6-4） |

### 6-2. 新しく作るものへの適用

- **実績は配置に1対1でぶら下げる**（`on delete cascade`）。**予定の値は写さない**
- 実績は**予定と違うときだけ**入れる（**空欄＝予定どおり**）。
  出力は「実績があれば実績、なければ予定」で**1回だけ**組み立てる
  → 同じ値が2か所に書かれる状態が**構造的に起きない**
- 中止は既存の `cancelled_at` の隣に**中止区分**を置き、矛盾を制約で拒否する（§3-4）。
  請求・支払いは**区分の初期値を写さず**、実績側は例外だけを持つ（空欄＝区分どおり）

### 6-3. 今あるテーブル

**既に DB で同期している写し（✅ 原則2 を満たす）**

| 写し | 元 | 仕組み |
|---|---|---|
| `shifts.jurisdiction_id` | 現場の管轄 | `shifts_fill_jurisdiction`（⚠️ #1 の穴あり） |
| `assignments.work_date` / `planned_*` | 枠の日付・時刻 | `assignments_fill_planned_times` ＋ `shifts_refill_assignment_times` |
| `assignments.is_confirmed` | 枠の確定状態 | `sync_assignment_confirmed` ＋ `assignment_inherit_confirmed` |
| 確定後の変更 → 仮組みへ戻す | ─ | `revert_shift_to_draft_on_change`（フラグを別に持たず、状態で表す） |

**意図的なスナップショット（✅ 原則3）**：`shifts` の時刻・班名（過去の配置は当時の値で請求する）／`notices.body`（送った文面）

**🔴 穴（元とずれうる）**
