## 決定事項

| # | 決定 | 理由 |
|---|---|---|
| 1 | **`S`（サブ）は廃止し、`L` をトグルに** | 9/2 の `assignment_role_simplify` で役割は2値。§2-8 の表のほうが古かった |
| 2 | 🔴 **IME 変換中はキーを一切拾わない** | 日本語入力は「やまだ」→ 変換 → `Enter` で確定する。拾うと**変換しただけで配置が走る**。氏名は全員日本語で入る画面なので、これは例外ではなく既定の経路 |
| 3 | 🔴 **フォーカスのあるボタン／リンクの `Enter` は奪わない** | 今日入れたバグ。奪うとそのボタンは**キーボード利用者にとって存在しないのと同じ**になる |
| 4 | 🔴 **`window.confirm` に業務の関門を預けない** | Chrome の「このページでこれ以上ダイアログを表示しない」が効くと、以後**何も表示せず false を返す**＝無反応・サーバに届かず・ログにも残らない。確認は画面の中に出す |
| 5 | **重なりの説明はアプリ、判定は DB のまま** | `23P01` が返って**きたあとだけ**引き直す。先に判定すると規則が DB とアプリの2か所になり、やがて食い違う |
| 6 | 🔴 **ダミーは重なりを1件も作らない** | 「仮組みの重なりは警告表示の材料になるから残す」は**誤りだった**。仮組みで重ねられるのは**管制が作業中に一時的にそうなる**という意味で、初期データが最初からその状態でよいということではない。結果として一括確定が最初から通らないダミーになっていた |
| 7 | **必要人数を平均 3.3 → 2.0 に**（実測 1.7） | 42枠で必要138名に対し隊員104名（うち15名は非現場・貸出）。**どう配っても足りず重ねるしかなかった**。9/2 に「帯 → 箱」へ組み替えた判断も、この密度でないと確かめられない |
| 8 | **`Backspace` は割り当てない**（`Del` のみ） | 取り消し手段が無い操作に、いちばん反射で押されるキーを重ねない |
| 9 | **手が出せない警告は出さない** | 両方とも別の盤面にある重なりは、この画面からは直せず一括確定も止めない。出すと「読まない帯」を作り、本当に効く警告まで埋もれる |
| 10 | **重なりは要確認の先頭・2列ぶん・省略なし** | 警告の中で**唯一「直さないと確定できない」**種類。他と混ぜると閉じられる帯の下へ流れて見えなくなる。文面も長い（相手が別管轄・別勤務のことが多く、得意先・管轄・区分まで無いと探せない） |

## ダミーデータの再生成結果

```
枠 42（日勤28／夜勤14）   稼働 90（現場75・非現場12・貸出3）＋ 過去 47
平均 2.0名/枠             重なり 0
未配置（プールに出る）14名  有給なのに現場にも居る人 0
```

**柴山が SQL Editor で投入済み**。件数は生成器の申告・生成物の再読み込み・DB の実測の3つで一致：

| テーブル | 件数 | 内訳 |
|---|---|---|
| `assignments` | 137 | 9/1：75 + 12 + 3 = 90 ／ 8/18（★経験の元データ・時刻なし）：47 |
| `shifts` | 66 | 9/1：42 ／ 8/18：24 |
| `sites` 42 ／ `guards` 104 ／ `ng_entries` 5 ／ `guard_qualifications` 53 | | |

生成側の直しは4点：
- 必要人数を実測に寄せた（5名の枠も1割残す ─ プレート3枚並びの折り返しを確かめるため）
- 配置時に時間帯の重なりを見る（規則は DB のトリガーと同じ：終了が開始以下なら翌日）。
  掛け持ちは禁じないが**最後の手段**にし、まだ何も入っていない人から先に配る
- 🔴 **非現場・貸出の隊員を先に確保**。後回しだと空いている人が尽き、**有給の人が現場にも立っている**データになっていた（実際になっていた）
- 「5枠に1つ不足させる」の判定が行の通し番号だったのを枠番号に。**コメントは5枠に1つと書きながら実際は42枠中15枠が不足**していた

`gen-seed.mts` の重なり除去は「確定どうしだけ落とす」をやめ**全件の安全網**にし、落としたときは警告を出すようにした（黙ると同じことが起きても気づけない）。

## 自戒

- 🔴 **検証コードのバグで、データを「問題なし」と誤って報告した。**
  seed の重なりを数えるスクリプトで `+09`（分なしオフセット）を `Date.parse` に渡し、
  **全比較が `NaN`** になって「0件」と出た。それを根拠に
  「重なりは操作で作られたもの／プールに抜け道があるはず」と柴山に伝えたが、**すべて誤り**だった
  （実際は seed に13件）。しかも**同型の誤りが本番コードにも潜んでいた**
  （`describeOverlaps` が時刻を文字列のまま並べ替えていた）。
  → 検証スクリプトも「動いた」ではなく**結果が妥当か**を見る。**0件は疑う。**

- 🔴 **キーボード操作を足すとき「奪ってよいキーか」を問わなかった。**
  `Enter` を無条件に `preventDefault` し、フォーカスのあるボタンを押せなくした。
  柴山が「一括確定できない」と報告するまで気づかなかった。
  **既存の操作を壊していないかを、足す前に確かめるべきだった。**

- 🔴 **「UI からは重複を作れません」と、確かめずに断定した。**
  現に作れていた（正確には最初から入っていた）。
  9/3 の自戒「手順を書く前に、その操作が何を通るのかを追う」と**同じ形**を繰り返している。

- 🟢 **良かった点**：dev サーバのログに `confirmShifts` の POST が**1件も無い**ことを確認してから原因を探した。
  「押しても何も起きない」を憶測でなく**サーバに届いていない**と切り分けられた。

- 🟢 **良かった点**：ダミー修正後、生成器の自己申告ではなく**生成物の SQL を独立に読み直して**0件を確認した。
  さらに柴山の DB 実測とも突き合わせて三重に一致を取った。
