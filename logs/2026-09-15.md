## 決定事項

| # | 決定 | 理由 |
|---|---|---|
| 1 | **週表は聞かずに作る**（柴山） | 「絶対必要」。日別と連動し、**週次画面でも配置操作ができる**こと |
| 2 | **`S-07` に印刷を統合**。新 ID を作らない | A表と週表は同じもので、印刷はその印刷スタイル。別画面にすると同じ表を2回作る |
| 3 | **実装順を段2-b へ前倒し** | 並行稼働の前提（完成条件7）である以上、最後尾に置く理由が無い |
| 4 | **週表に一括確定は置かない** | 1日のつもりで押すと7日分が確定する。確定は日別に降りてから |
| 5 | **プールは基準日で絞る**。列ヘッダで基準日を移す | 「未配置」は日が決まって初めて意味を持つ |
| 6 | **楽観更新を入れない** | 週表は5段深く、画面の更新規則がもう1つ増える。1名体制では読めなくなるほうが高くつく |
| 7 | 🔴 **週表は本番に出さない** | 明日は「ローカルで作成中です」と言って見せる |

## 自戒

- 🔴 **編集後に検査せず「再読み込みしてください」と言い、構文エラーのまま渡した。**
  `return (` の直後に JSX コメントを置いた初歩的な誤り。
  → **編集したら必ず `tsc` を通してから渡す。**

- 🔴 **仕様を確認せずにテスト項目を書いた。**
  「同じ日の別現場に置けば『置けません』が出るはず」と言ったが、
  **仮組みでは重複を止めないのが仕様**だった。確認項目こそ、実装を読んでから書く。

- 🔴 **一時ファイルをプロジェクト直下に散らかした**（本番 JS チャンク7本と HTML）。
  `$TMPDIR` が解決できずに落ちた。**scratchpad を使う。**

- 🟢 **良かった点**：ポリシー名を推測して「0件」を出したとき、結果を疑って実際の名前を確認した
  （`control` を含むという思い込みだった）。

- 🟢 **良かった点**：`grep -P` がロケールで失敗したのに「なし」と出たとき、
  それを検証と見なさず node で**検出器の自己テストから**測り直した。

- 🟢 **良かった点**：SQL の確定が効かなかったとき、推測で「もう一度流して」と言わず、
  **トリガの発火条件を読んで**「流されたのは修正前」と特定した。
