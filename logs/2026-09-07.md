## 決定事項

| # | 決定 | 理由 |
|---|---|---|
| 1 | 🔴 **中止に `work_kind` の `dayCancel`/`nightCancel` を使わない** | あのラベルは「**日勤現中**」＝**現着中止**であり、隊員が現場に着いたあとの中止。**稼働が立つ＝請求対象になりうる**。同じ列に入れると ShiftMax への引き渡し（段3）で勤務区分が「現中」として出て**請求が変わる**。→ `cancelled_at` として別に持つ |
| 2 | 🔴 **中止は「消す」ではなく「状態が変わる」** | 管制の要望そのもの。**誰を入れていたかが残らないと、空いた隊員をどこへ回すか判断できない**。中止枠は一括確定の対象外／「不足」「資格」警告も出さない（中止にするほど画面が汚れるのを防ぐ） |
| 3 | 🔴 **`sites` は「作れる」と「書き換えられる」を分ける**<br>INSERT → `control`／UPDATE・DELETE → `admin` | 上記の一次情報から。**新規現場を作れるのが admin だけでは、いちばん急いでいる場面で管制の手が止まる**＝第1弾の効果を自分で潰す。一方、取込済みマスタを書き換えられると引き渡しの突き合わせが壊れる。**増やすのは許し、変えるのは許さない**。→ `requirements.md` §3 決定 #4 に反映 |
| 4 | **中止と削除は別のボタン** | 用途が違う。**中止**＝現場が飛んだ（記録は残す）／**削除**＝そもそも間違えて作った枠（残す価値がない）。中止しかないと、打ち間違いの枠が盤面に居座り続ける |
| 5 | **削除で消えるのは枠だけ。現場（マスタ）は消さない** | 現場は他の日の枠からも参照され、ShiftMax 由来のマスタでもある |
| 6 | **削除の確認は「何名ぶん消えるか」を出してから** | `assignments` は `on delete cascade` で一緒に消える。件数を出さずに押させると、**消えたことに後で気づく**作りになる |
| 7 | **新規現場は仮番号（`TMP-`）で通す** | `site_code` と `guard_target_no`（べんり君の警備先番号）は NOT NULL だが、**新しい仕事が入った瞬間に管制がこれを知っているとは限らない**。番号を要求すると、いちばん急いでいるときに手が止まる。→ 🔴 **仮番号のままでは段3で引き渡せない**。採番の主体は要確認 |
| 8 | **得意先は「新規現場のときだけ」聞く** | 既存現場は現場マスタが得意先を持っており、ここで聞くと**どちらが本当かが二重になる** |
| 9 | **得意先そのものの新規作成はしない** | ShiftMax 由来のマスタで、請求（第2弾）の突き合わせに使う。勝手に増やすと合わなくなる |
| 10 | **現場の詳細設定画面は、追加ダイアログと分けたままにする** | 1つにまとめると、**急いでいるときに詳細画面の重さを毎回引き受ける**ことになる。それが AIK assign で起きたことだと理解している |

## 自戒

- 🔴 **「現場を追加」に得意先を入れ忘れた。**
  最小構成で速く出すことを優先した結果、**請求にも盤面のまとまりにも効く項目**を落としていた。
  柴山に「仕様ですか」と聞かれるまで気づかなかった。
  **削る判断をしたなら、削ったことを自分から言うべきだった。**「聞かれなければ気づかれない」は
  黙って仕様を決めているのと同じ。

- 🔴 **自分で作った機能を、自分で見えなくした。**
  得意先タブで絞り込んでいると追加した枠が画面に出ない ─ これは
  **既存の絞り込みを踏まえずに新しい導線を足した**結果。
  9/4 の自戒「既存の操作を壊していないかを、足す前に確かめるべきだった」と**同じ形**。
  今回は壊してはいないが、**既存の状態（絞り込み中）を考えずに作った**点で変わらない。

- 🔴 **RLS を確かめずに「現場を作れる」機能を作った。**
  `sites` が admin 限定であることは、同じリポジトリのマイグレーションに書いてある。
  **書く前に読めば分かったこと**を、動かしてから気づいた。

- 🟢 **良かった点**：`dayCancel`/`nightCancel` を見つけたとき、**すぐ使わずにラベルを確認した**。
  「日勤現中」＝現着中止と分かり、請求に効く別物だと切り分けられた。
  ここで飛びついていたら、**引き渡しで勤務区分が化けて請求が変わる**ところだった。

- 🟢 **良かった点**：「枠ができない」を憶測で直さず、**dev サーバのログで切り分けた**。
  `addShift` が3回とも 200 で完了していること、URL に `c=CU0001` が付いていることの2点から
  「作られているが見えていない」と特定できた。9/4 の自戒がここでは効いた。

- 🟢 **良かった点**：`refresh()` の使い方を**推測せず Next.js の同梱ドキュメントで確認**した
  （`node_modules/next/dist/docs/.../refresh.md`）。結果、原因はそこではないと切り分けられた。
