## 決定事項

| # | 決定 | 理由 |
|---|---|---|
| 1 | **カード詳細の詰めより D&D を先に**やる | D&D を入れるとプレート／カードの markup 自体が変わる。先に細部を詰めると二度手間 |
| 2 | 🔴 **予定時刻は DB のトリガーで埋める** | 重複を止めているのは `assignments_no_overlap` だけで、この制約は `planned_*` が入った行しか見ない。アプリに委ねると**書き忘れた瞬間に安全網が黙って外れる**。落ちずに「止まらなくなる」ため誰も気づけない |
| 3 | **保存の可否は DB が決める。アプリに同じ判定を二重に書かない** | NG・資格不足・人数超過は置ける（§2-5）。楽観更新中に警告が古くなるのは承知で受ける |
| 4 | **押しても何も起きないボタンは置かない**（カードの `⋯` を削除） | 壊れていると読まれる |
| 5 | 🔴 **JSX を Server → Client の props で渡さない** | 「Link はサーバで描くもの」という**前提が誤り**だった。渡すのはプレーンなデータだけにする |
| 6 | 🔴 **プールは「その日すでに稼働がある人」を出さない** | 人は管轄をまたいで1人しかいない。プールは画面の都合ではなく**その日の実態**で決まる |
| 7 | 🔴 **「要 再引き渡し」バッジと `changed_after_confirm` 列を廃止**（柴山の指摘）<br>→ 確定後に変わったら**仮組みに戻す** | ①まだ一度も引き渡していないのに「再度渡せ」と言っていた<br>②状態の語が3つに増えていた。言いたいのは「確定し直す必要がある」だけ<br>③引き渡し済みか否かは段3の**引き渡し履歴**が持つべき情報 |
| 8 | `一括確定` は**いま表示している仮組み**だけを対象にし、確認を1回挟む | 押した範囲と変わった範囲を食い違わせない |

## 自戒

- 🔴 **動作確認の手順を、自分で成立を確かめずに人に渡した。**
  「確定済みの枠にいる隊員を、重なる別の枠へ移動して弾かれるか」と書いたが、
  **移動は同一人物が2枠に同時に居ることにならないので制約に触れない**。
  柴山に無駄な操作をさせたうえ、「普通におけた」を不具合として報告させてしまった。
  **手順を書く前に、その操作が何を通るのかを追うべきだった。**

- 🔴 **「Link はサーバで描くもの」という前提を確かめずに設計した。**
  そのために JSX を RSC 境界越しに渡す構造にし、key 警告を自分で作った。
  `next/link` はクライアントでも動く。**思い込みを一度も検証していない。**
  9/2 の「Next.js は自動で nonce を付与する」と**同じ形の誤り**を繰り返している。

- 🔴 **「要 再引き渡し」は、自分では最後まで違和感を持てなかった。**
  まだ一度も引き渡していないのに「再度渡せ」と出しており、
  柴山に「謎の文言」と言われるまで気づかなかった。
  設計文書（§2-7）に書いてあることを、**段階の前後を確かめずにそのまま実装した**。

- 🟢 **良かった点**：`TaskStop` のあと**ポート 3000 を確認して**node 本体が生き残っているのを見つけ、
  プロセスを特定してから落とした。9/2 の自戒（止めたと言うなら確認する）は機能した。

- 🟢 **良かった点**：dev サーバのログを見て、**報告されていない hydration mismatch** を先に見つけた。
  放置すれば「ドラッグできない」で詰まっていた（9/2 の CSP と同じ壊れ方）。
